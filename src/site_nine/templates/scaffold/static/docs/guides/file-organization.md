# File Organization Guide

Where to place files when working on site-nine.


## Golden Rule: Keep Project Root Clean

**⚠️ CRITICAL: Never create temporary or work files in project root or source directories.**

All agent work artifacts belong in `.opencode/work/`. Project root should only contain production code, config,
shipped documentation, and standard files (README, LICENSE).

## Directory Structure

```
.opencode/
├── commands/          # OpenCode slash commands
├── data/              # Reference documentation
├── docs/              # Project documentation
│   ├── adrs/         # Architecture Decision Records
│   ├── guides/       # How-to guides
│   └── roles/        # Agent role definitions
├── skills/            # OpenCode skill definitions
├── scripts/           # Permanent utility scripts
└── work/              # 🎯 All agent work artifacts
    ├── epics/        # Epic tracking
    ├── missions/     # Mission logs
    ├── planning/     # Planning documents
    ├── scripts/      # Temporary task scripts
    ├── sessions/     # Session tracking
    ├── tasks/        # Task files
    └── test-plans/   # Test planning
```

## The .opencode/work/ Directory

Your workspace for all mission artifacts.

### work/missions/

Mission logs documenting your work session.

**Naming:** `YYYY-MM-DD.HH:MM:SS.role.persona.codename.md` (auto-generated by `s9 mission start`)

**Update throughout your mission** (it's a living document!) with work log entries, decisions, files changed,
blockers, and learnings.


### work/tasks/

Task tracking files (auto-generated by `s9 task create`).

**Naming:** `TASK-ID.md`

**Update via `s9 task` commands** (don't edit directly).


### work/scripts/

Temporary, task-specific scripts.

**Naming:** `TASK-ID-descriptive-name.ext`

**Must include:** Header with task ID, mission ID, purpose, deletion criteria.

**Clean up when task/mission completes.**

**Not for:** Permanent utilities (use `scripts/` in project root).


### work/epics/

Epic planning and coordination (auto-generated by `s9 epic create`).


### work/planning/

General planning docs not tied to specific tasks.


### work/sessions/

OpenCode session tracking (system-managed, don't create manually).


### work/test-plans/

Test strategy and planning documents.

## Other Directories

### .opencode/docs/

Project documentation: ADRs, architecture docs, how-to guides, role definitions.

**Add:** Long-term documentation, finalized guides.

**Don't add:** Temporary notes, WIP docs, mission-specific logs.


### .opencode/skills/

OpenCode skill definitions and workflows.

**Structure:** `skills/skill-name/` with `SKILL.md`, `scripts/`, `reference/`


### .opencode/scripts/

Permanent utility scripts used repeatedly.

**Not for:** One-time scripts, task-specific automation (use `.opencode/work/scripts/`).

## Common Scenarios

**Task script:** `.opencode/work/scripts/TASK-ID-description.py`

**Work session notes:** Your mission file (update throughout session!)

**Feature planning:** Task notes (`s9 task update`), epic file, or `.opencode/work/planning/`

**Permanent script:** Refactor, document, move from `.opencode/work/scripts/` to `scripts/`

**Architecture decision:** `.opencode/docs/adrs/` (follow adr-workflow.md)

**Agent guide:** `.opencode/docs/guides/`

## Cleanup Guidelines

### Temporary Files

Clean up `.opencode/work/` files when mission/task ends or scripts are promoted.

**Keep:** Mission logs (history), task files (system-managed), epics (until complete), handoffs (until accepted).


### Permanent Files

Only add to `.opencode/docs/`, `.opencode/skills/`, `.opencode/scripts/` if providing long-term value.

## Anti-Patterns

### ❌ Project Root Pollution

Don't create `./temp-script.py`, `./notes.md`, `./TODO.txt` in project root.

**Why:** Pollutes structure, accidental commits, confuses developers.

**Do:** Use `.opencode/work/scripts/`, mission file, task files.


### ❌ Status Files

Don't create `STATUS.md`, `PROGRESS.txt`, `CURRENT_WORK.md`.

**Why:** Confusion, becomes stale, duplicates database info.

**Do:** Use `s9 task update`, mission file, `s9 dashboard`.


### ❌ Temporary Docs in docs/

Don't create `.opencode/docs/my-notes.md`, `.opencode/docs/wip-design.md`.

**Why:** Mixes temporary/permanent, unclear authority.

**Do:** Use `.opencode/work/planning/` for WIP, move to docs/ when finalized.


### ❌ Permanent Scripts in work/scripts/

Don't store repeatedly-used scripts in `.opencode/work/scripts/`.

**Why:** May be deleted, not discoverable, not in path.

**Do:** Move to `scripts/`, document in README.

| ADR | `.opencode/docs/adrs/` | No | `ADR-001-use-sqlite.md` |
| Skill | `.opencode/skills/` | No | `task-create/SKILL.md` |


## Summary

1. ✅ All work artifacts in `.opencode/work/`
2. ✅ Mission files are living documents
3. ✅ Clean up temporary files when done
4. ✅ Link scripts to tasks via naming
5. ❌ Never create temp files in project root
6. ❌ Never create status files
7. ❌ Don't pollute docs/ with WIP

**When in doubt:** Temporary → `.opencode/work/`, Permanent → `.opencode/docs/` or `scripts/`
