## Technical Notes

**Conversation Auto-Creation Logic:**
The `get_or_create_conversation()` method implements the auto-creation rules from ADR-008:
1. Checks for existing open conversation between two missions
2. If closed conversation exists, creates NEW conversation (fresh start pattern)
3. If no conversation exists, creates new one
4. Normalizes participant order (lower ID first) for consistent lookups

**Threading Rules:**
- Conversations (1-on-1): Flat structure, no threading (parent_message_id=NULL, thread_root_id=NULL)
- Discussions (scoped): Threaded structure, unlimited depth
- When replying: parent_message_id points to immediate parent, thread_root_id points to root
- Root messages have both fields NULL

**Scope Validation:**
- Role scope: Validates role against core.roles.Role enum
- Epic scope: Requires valid epic_id (foreign key validation)
- All scope: No additional validation needed

**ID Generation:**
- Conversation IDs: Sequential CONV-0001, CONV-0002, etc.
- Message IDs: Priority-based MSG-H-0001, MSG-M-0002, etc.
- Uses message_ids.py utilities for message ID generation
- Custom implementation for conversation IDs (simpler pattern)

**Dependencies:**
- Requires database tables from OPR-H-0082 migration
- Uses message ID utilities from message_ids.py (OPR-H-0083)
- Ready for CLI integration (OPR-H-0088)
