## Technical Notes

**Race Condition Fix:** The original race condition occurred when multiple concurrent `s9 summon` calls would:
1. Call `persona_suggest` (read operation) - both get same persona
2. Call `mission_persona_record` (write operation) - both try to use same persona

**Solution:** Replace the two-step read-then-write with a single atomic operation:
- `PersonaManager.claim_persona()` uses `UPDATE ... WHERE name = (SELECT ... ORDER BY mission_count ASC LIMIT 1) RETURNING *`
- This SELECT + UPDATE happens in a single transaction, preventing race conditions
- No need to call `persona_suggest` in the critical path (it's now informational-only)
