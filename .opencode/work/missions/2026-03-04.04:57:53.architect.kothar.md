## Technical Notes

### Critical Implementation Nuances

1. **`worker_spawn.py` repo root resolution**: The current `tool_dir.parent.parent` pattern breaks
   when an Admin agent is itself running inside a worktree. Must be replaced with
   `get_main_worktree_root()` (using `git worktree list --porcelain`).

2. **Sequencing**: Mission ID is not known until `mission_init` runs inside the first `opencode run`.
   Worktree must exist before that run (to set `cwd`). Solution: UUID staging name → rename after
   mission ID is known → `git worktree repair`.

3. **Symlink targets**: `.opencode/data/` and `.opencode/work/` must be symlinked to the main
   worktree's copies. `.opencode/tools/`, `.opencode/skills/`, `.opencode/docs/` remain as real
   directories in the worktree (so workers can edit them in isolation if needed).

4. **`git clean` prohibition**: Worker agents must not run `git clean -fdx`, which would destroy the
   `.opencode/data/`, `.opencode/work/`, and `.venv/` symlinks.

5. **Worktree location**: `../.s9-workers/<id>/` is outside the repo root, so it never appears in
   `git status` of the main worktree. The `.gitignore` does not need updating.
