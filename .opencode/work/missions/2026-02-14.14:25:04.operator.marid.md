## Technical Notes

### OPR-H-0083 (Message ID Generation)

**Design Decisions:**
- Followed existing task ID generation pattern for consistency
- Simpler format (MSG-P-NNNN vs ROLE-P-NNNN) because messages aren't role-specific
- Global sequential numbering ensures unique IDs across all priorities
- Validation uses regex + buzz library for consistent error handling

**Thread Safety:**
- SQLAlchemy's `engine.begin()` provides transaction isolation
- Same race condition window as tasks (MAX query + insert pattern)
- Acceptable for CLI tool usage (single-threaded, SQLite write serialization)

**Test Strategy:**
- Tests skip if messages table has foreign key constraints (migration not run yet)
- Tests create simplified table without constraints for unit testing
- Once migration complete, all tests will run against real schema

### OPR-H-0093 (Epic Scoping Validation)

**Design Decisions:**
- Validation runs before handoff processing (fail fast approach)
- Uses existing error handling pattern (buzz.require_condition + TaskError)
- Clear, actionable error messages that include both epic IDs
- Validation only applies when mission has epic_id (NULL = general mission, no restriction)

**Implementation Pattern:**
- Query mission first to get epic_id
- Only query task if mission is epic-scoped (optimization)
- Single transaction ensures data consistency
- Follows existing TaskManager validation patterns

**ADR-009 Compliance:**
- Supports all three mission scoping modes:
  1. Task-scoped: mission.epic_id is NULL, mission.task_id is set (existing behavior, no change)
  2. Epic-scoped: mission.epic_id is set, validates task belongs to same epic (new validation)
  3. General: mission.epic_id is NULL, mission.task_id is NULL (no restrictions, no change)
