**Paradigm Shift:** From loosely coupled CLI tool to tightly integrated OpenCode platform

**Core Architecture:**

1. **Session-First Design:**
   - Session ID becomes primary correlation key in database (`opencode_session_id TEXT UNIQUE`)
   - Missions are inherently tied to OpenCode sessions (no detection needed)
   - O(1) lookups, perfect synchronization

2. **Automatic Lifecycle Management:**
   - Plugin hooks `session.created` → Auto-register mission
   - Plugin hooks `session.updated` → Automatic heartbeats
   - Plugin hooks `session.deleted` → Auto-end mission with summary
   - Plugin hooks `session.idle` → Desk mode awareness
   - Zero manual intervention required

3. **Desk Mode Orchestration:**
   - Background workers run in headless OpenCode sessions
   - Admin summons workers: `s9 agent summon engineer --mode desk`
   - Workers await messages in polling loop
   - Admin coordinates via messaging system
   - Director only talks to Admin (reduced cognitive load)

4. **Enhanced Automation:**
   - Auto-generate summaries from session context (messages, diffs, tools)
   - Detect stuck agents (idle timeout) and send helpful notifications
   - Auto-claim tasks when agent modifies related files
   - Suggest task completion based on diffs
   - Rich context enables intelligent automation

**Implementation Plan:**
- **Phase 1:** Database schema + CLI foundation (session-based commands)
- **Phase 2:** Basic plugin (lifecycle hooks, auto-registration)
- **Phase 3:** Desk mode orchestration (summoning, messaging, dismissal)
- **Phase 4:** Enhanced automation (summaries, stuck detection, task claiming)
- **Phase 5:** Documentation & rollout
- **Phase 6:** Advanced features (LLM summaries, webhooks, multi-level orchestration)

**Benefits:**
- ✅ Eliminates manual coupling (fully automatic)
- ✅ Zero zombie missions (impossible to have mission without session)
- ✅ Automatic heartbeats (every session activity)
- ✅ Rich automation (leverages session context)

- ✅ Reduced cognitive load (invisible infrastructure)

**Alternatives Rejected:**
1. Keep loose coupling (status quo - doesn't solve fundamental problems)

### Technical Discoveries

**OpenCode Plugin System:**
- Robust event-driven plugin API with session lifecycle hooks
- Plugins can execute shell commands and access OpenCode SDK
- `session.deleted` event provides session ID and context
- Plugins auto-load from `.opencode/plugins/` directory

**Session-Mission Correlation:**
- Previous approach considered: Direct database field (`opencode_session_id`)
- **Revised approach:** Leverage existing `OpenCodeSessionManager.detect_session()` cascade
- Detection methods (in order of priority):
  1. DB recency - Query OpenCode SQLite DB for recent session
  2. UUID marker - Search for marker in session data (set during `rename-tui`)
  3. Content correlation - Compare git changes with session diffs
  4. Diff recency - Find most recent session diff file
  5. Session recency - Fallback to most recent session file
- Provides reliable detection without database changes
- Already proven in production (`rename-tui` command)

**Implementation Complexity:**
- Database migration: Required (`opencode_session_id` and `mode` columns)
- CLI commands: Moderate (session-based signatures, new commands for desk mode)
- Plugin development: Significant (lifecycle hooks, context parsing, desk mode handling)
- Skills: Optional enhancements (auto-registration reduces need)
- Desk mode orchestration: New capability (summoning, message polling, coordination)
- Total effort: ~2-3 weeks for full implementation + testing

## Technical Notes

### OpenCode Plugin System

**Available Session Events:**
- `session.created` - When a new session starts
- `session.deleted` - When a session is deleted/closed
- `session.idle` - When a session becomes idle
- `session.error` - When a session encounters an error
- `session.updated` - When session metadata changes

**Plugin Capabilities:**
- Can execute shell commands via Bun's `$` API
- Can access OpenCode SDK client for API calls
- Can hook into lifecycle events
- Local plugins: `.opencode/plugins/*.js` or `.opencode/plugins/*.ts`
- npm plugins: Specified in `opencode.json` config

**Mission Identification Challenge:**
- Plugins receive session context but need to map sessions to missions
- **Solution:** Use existing `OpenCodeSessionManager.detect_session()` cascade:
  1. DB recency (most reliable) - Query OpenCode SQLite for recent session
  2. UUID marker - Search for marker in session data
  3. Content correlation - Compare git changes with session diffs
  4. Diff recency - Find most recent session diff
  5. Session recency - Fallback to most recent session
- Already proven in production (`rename-tui` command)
- No database schema changes required
