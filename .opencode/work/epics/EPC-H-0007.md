## Description

Build a full-featured Textual TUI for site-nine, launchable via the bare s9 command. Includes dashboard, missions, tasks, messages, ADRs, and mission histories screens with list+preview+full-page navigation, vim-style keybindings, and arrow key support.

## Goals

- Provide a navigable TUI accessible via the bare `s9` command in any TTY
- Cover all major data entities: dashboard, missions, tasks, messages, ADRs, histories, epics
- Consistent UX: list+preview+fullpage pattern across all screens, vim+arrow keybindings

## Success Criteria

- `s9` launches TUI; `s9 --no-tui` falls back to help text
- All 7 screens (Dashboard, Missions, Tasks, Messages, ADRs, Histories, Epics) render data
- j/k and up/down navigate lists; Enter opens full-page; Escape closes; / filters
- gg/G jump to top/bottom; d/u scroll half-page in full-page views
- Tab toggles sub-views (Messages: conversations vs discussions)
- All screens degrade gracefully when DB is empty or unavailable
- Comprehensive test suite passes

## Architecture Design (ARC-H-0228)

│   ├── tasks.py        # TasksScreen - task queue with filters
│   ├── messages.py     # MessagesScreen - conversations + discussions
│   ├── adrs.py         # ADRsScreen - architecture decision records
│   ├── histories.py    # HistoriesScreen - all missions as historical record
│   └── epics.py        # EpicsScreen - epics with progress

│   ├── preview_pane.py # PreviewPane - markdown/text preview of selected item
│   ├── full_page.py    # FullPageView - scrollable full content screen
│   └── filter_bar.py   # FilterBar - search/filter input
└── styles/
    └── app.tcss        # Global TCSS stylesheet
```

### Navigation Model

- Sidebar navigation: numbered keys 1-7 switch screens; displayed in left panel
- Within a screen: j/k (vim) or up/down (arrows) move selection in the list
- gg = jump to top, G = jump to bottom
- Enter = push FullPageView screen for the selected item
- Escape = pop back to list
- / = focus FilterBar
- Tab = toggle sub-view (Messages screen)
- q = quit application
- ? = help overlay

```

### Data Access Pattern

All screens import managers directly from `site_nine.*`:
- `MissionManager`, `TaskManager`, `MessageManager`, `ADRManager`, `EpicManager`
- Database instance shared at App level, passed to screens on mount
- Each screen loads data in `on_mount()` and refreshes on timer if needed
- Errors caught and shown in preview pane (no crashes)
